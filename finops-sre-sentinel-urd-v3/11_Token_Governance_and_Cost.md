## 11.1 Why Token Governance Matters

Unconstrained AI agents can quickly become expensive. Without governance:
- A single complex debugging session could cost **$5-8** in API fees
- Runaway prompts could exhaust daily budgets in minutes
- Wasted tokens from retries and loops multiply costs

**For your project (using NVIDIA free models):** Token governance is about **efficiency and reliability**, not cost. The governance framework is designed to work with **any model provider** - including paid ones for production.

## 11.4 Token Tracking & Wasted Token Analysis

### 11.4.1 What Gets Tracked

| Metric | Description | Granularity |
|--------|-------------|-------------|
| Input tokens | Tokens consumed by prompt/context | Per tool execution |
| Output tokens | Tokens generated by AI response | Per tool execution |
| Cached tokens | Tokens served from cache (avoided cost) | Per tool execution |
| Wasted tokens | Tokens used but not needed (retries, loops) | Per tool execution |
| Total daily burn | Cumulative tokens used in 24h | Daily |
| Budget remaining | Tokens remaining before hard cap | Real-time |

### 11.4.2 Wasted Token Categories & Reasons

| Waste Category | Description | Prevention Strategy |
|---------------|-------------|---------------------|
| **Retry Waste** | AI retries failed calls with full context | Exponential backoff, max 2 retries |
| **Loop Waste** | AI enters reasoning loop without progress | Max steps limit (5 steps per tool) |
| **Over-Query Waste** | AI queries more data than needed | Prompt optimization, limit results |
| **Context Bloat** | Unnecessary context passed to model | Trim context to relevant portion only |
| **Approval Polling Waste** | Polling for approval status | Use SSE push instead of polling |

## 11.5 Hard Budget Caps & Throttling

### 11.5.1 Budget Configuration

```yaml
token_budget:
  daily_limit: 100000        # Hard cap per day
  warning_threshold: 0.80    # Warn at 80% consumption
  critical_threshold: 0.95   # Critical alert at 95%
  auto_throttle: true        # Auto-throttle when budget is low
  
  per_tool_limits:
    diagnose_transaction_latency: 25000
    analyze_cloud_spend_anomaly: 25000
    remediate_unhealthy_pod: 20000
    verify_compliance_drift: 20000
    buffer: 10000            # Reserve for critical operations
    
  throttle_actions:
    - threshold: 0.80
      action: "notify_admin"
    - threshold: 0.90
      action: "reduce_concurrency"
    - threshold: 0.95
      action: "read_only_mode"
    - threshold: 1.00
      action: "block_all_non_essential"
```

### 11.5.2 Throttling Behavior

| Budget Level | System Behavior |
|-------------|-----------------|
| **< 80%** | Normal operation - all tools available |
| **80-90%** | Notification sent to admin, reduce concurrent executions to 50% |
| **90-95%** | Read-only mode - only diagnostic tools, no remediation |
| **95-100%** | Critical alerts, only basic tools allowed |
| **> 100%** | All non-essential tools blocked, emergency admin override required |

## 11.6 Cost-Aware Routing

To optimize token usage, the system routes tasks to the most cost-effective model:

| Task Type | Recommended Model | Complexity | Cost |
|-----------|------------------|------------|------|
| Simple metrics query | Ollama (Llama 3.2 8B) | Low | $0 |
| Log pattern analysis | DeepSeek V4 Flash (NVIDIA) | Medium | $0 |
| Complex root cause analysis | Llama 4 Maverick (NVIDIA) | High | $0 |
| Compliance verification | DeepSeek V4 Flash (NVIDIA) | Medium | $0 |
| Emergency (when NVIDIA down) | Ollama fallback | Any | $0 |

**Routing Logic:**
```yaml
cost_aware_routing:
  enabled: true
  default_model: "nvidia_deepseek_v4_flash"
  
  routing_rules:
    - tool: "diagnose_transaction_latency"
      when: "input_threshold_ms < 1000 AND result_limit < 50"
      use: "ollama_llama3_8b"
    
    - tool: "diagnose_transaction_latency"
      when: "input_threshold_ms >= 1000 OR result_limit >= 50"
      use: "nvidia_deepseek_v4_flash"
    
    - tool: "analyze_cloud_spend_anomaly"
      use: "nvidia_deepseek_v4_flash"
    
    - tool: "remediate_unhealthy_pod"
      use: "nvidia_deepseek_v4_flash"
    
    - tool: "verify_compliance_drift"
      use: "nvidia_deepseek_v4_flash"
      
  fallback_chain:
    - "nvidia_llama4_maverick"     # If DeepSeek fails
    - "ollama_llama3_8b"           # If all NVIDIA fails
    - "mock_response"              # Last resort
```

## 11.7 Semantic Caching

Frequent read-only queries are cached to **reduce token waste**:

| Cache Rule | TTL | Example Query |
|------------|-----|---------------|
| Cluster health | 30 seconds | "Show me health of production namespace" |
| Compliance drift | 5 minutes | "Check PCI-DSS compliance status" |
| Cost anomalies | 15 minutes | "Any cloud spend spikes today?" |
| Service topology | 1 minute | "Show service dependency graph" |

**Cache Hit Ratio Target:** > 40% of all read-only queries should be cache hits.
